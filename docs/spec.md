# Спецификация: Жевчик

Документ описывает контракты бота и то, чем каждая гарантия проверяется. Общая конструкция продукта - в `DESIGN.md`. Все числа, названные значениями по умолчанию, лежат в настройках чата (`src/settings/schema.json`) и меняются на экране админа без правки кода.

## 1. Задача одной строкой

Участники Telegram-чата получают карму за пользу, спамеры уходят в баню, всё видно в Mini App; судья - модель Jev.

## 3. Решения

### 3.1 Стек

- TypeScript, Node.js 22, grammY, Hono.
- PostgreSQL 16.
- Клиент Jev: прямой HTTP к `POST https://api.typesafe.ai/v1/systemone`. Суммарное число попыток одной оценки не больше трёх.
- Mini App: клиент на TypeScript без фреймворка, собирается esbuild. Бюджет: сумма размеров HTML, CSS и JavaScript не больше 150 КиБ при сжатии Brotli. Проверяется командой `npm run budget` на production-сборке, которая падает при превышении. Изображения и Telegram SDK в бюджет не входят.
- Поставка: `docker-compose.yml`, сервисы `bot`, `web`, `db`; образы собираются под `linux/arm64`.
- Веб слушает локальный порт по HTTP. HTTPS обеспечивает внешний обратный прокси (например, Caddy).

### 3.2 Границы наружу

| Граница | Настройка |
|---|---|
| Telegram Bot API | `TELEGRAM_BOT_TOKEN`; long polling; `allowed_updates`: `message`, `edited_message`, `message_reaction`, `message_reaction_count`, `chat_member`, `my_chat_member`, `callback_query` |
| Jev | `TYPESAFE_API_KEY`; модель `jev-1.13.0`, алиасы запрещены |
| Модель описания | OpenAI-совместимый endpoint: `VISION_BASE_URL`, `VISION_MODEL`, `VISION_API_KEY`; без них медиа не описывается, остальное работает |

Каждая граница закрыта интерфейсом с управляемым двойником для тестов. Двойник допустим только на этих трёх границах. База в тестах настоящая. Источник времени и источник случайности передаются явно.

### 3.3 Ключи данных

- Каждая доменная запись содержит `chat_id`.
- Участник чата уникален по `(chat_id, user_id)`.
- Сообщение уникально по `(chat_id, message_id)`.
- Именная реакция уникальна по `(chat_id, message_id, actor_kind, actor_id, reaction_type)`, где `actor_kind` - `user` или `chat`.
- Снимок анонимных реакций уникален по `(chat_id, message_id, reaction_type)`.
- Настройка уникальна по `(chat_id, key, version)`.
- `chat_id` для запросов Mini App берётся только из проверенного контекста, раздел 3.8.

### 3.4 Карма

Карма - сумма событий журнала. Каждое событие хранит причину, источник, ссылку на сообщение и ключ идемпотентности. Кэш текущего значения пишется одной транзакцией с событием. Значения хранятся как `numeric(12,4)`, округление только при отображении.

Реакция участника A на сообщение участника B:

```
delta = base × message_factor(k_message) × pair_factor(k_pair) × voter_weight(karma_A)
message_factor(k) = 1 / (1 + ln(k))
pair_factor(k)    = 1 / (1 + ln(k))
voter_weight(x)   = 1 + ln(1 + max(0, x) / K)
```

`k_message` - порядковый номер сигнала под этим сообщением, `k_pair` - порядковый номер сигнала от A к B за последние 30 суток; оба начинаются с 1. Для минусующей реакции `base` отрицательный, формула та же. Положительное начисление умножается на надбавку за серию.

Реакции Telegram:
- `message_reaction`: считается разность множеств `new_reaction − old_reaction` и `old_reaction − new_reaction`; каждая добавленная и снятая реакция обрабатывается отдельно.
- `message_reaction_count`: хранится последний снимок количества по типу; начисляется или отменяется только разность со снимком, без `pair_factor` и `voter_weight`. Снимок и события пишутся одной транзакцией. Обновление с `date` меньше сохранённого игнорируется.
- Минусующая реакция не учитывается, если у голосующего карма ниже `minus_min_karma` или не выше порога первого наказания (раздел 3.7), а также сверх суточного лимита (скользящие 24 часа).

Сигналы лестницы:
- Ответ определяется `reply_to_message`.
- Цитата - ответ с полем `quote`.
- Диалог - автор исходного сообщения ответил на прямой ответ другого участника в той же цепочке не позднее `dialog_window_hours` (по умолчанию 24 часа).
- Благодарность - ответ с `is_thanks` не ниже порога.
- На одну связь двух сообщений действует только самый дорогой подтверждённый сигнал. Более дорогой заменяет дешёвый: компенсирующее событие и новое начисление.
- Ответ, у которого `rude` не ниже порога при тоне `serious`, сигналов ответа и диалога не даёт.
- Стикер или гифка в прямом ответе, которые Jev признал уместными (`media_fits` не ниже порога), дают сигнал «реакция». Без описания медиа сигнал не начисляется.
- Серия сообщений одного автора подряд: начисление Jev за k-е сообщение подряд умножается на `1 / (1 + ln(k))`.

Убывание: за каждый полный период `decay_period_days` (по умолчанию 30 суток) неактивности после срока тишины

```
new = max(lower_bound, old − decay_rate × abs(old))
```

Серия: активная неделя - неделя ISO в часовом поясе чата (настройка `timezone`, по умолчанию `Asia/Tashkent`), в которой есть хотя бы одно сообщение участника с `is_flood` ниже порога. Серия растёт при смежных активных неделях и обнуляется после первой пропущенной. Надбавка `1 + min(streak_bonus_max, streak_bonus_per_week × недели серии)` умножает положительные начисления.

Плановые задачи идемпотентны по ключу (задача, период, участник или чат).

Значения по умолчанию:

| Параметр | Значение |
|---|---|
| Реакция, `base` | 1 |
| Ответ | 2 |
| Цитата | 3 |
| Диалог | 4 |
| Благодарность | 6 |
| Минусующая реакция, `base` | -1 |
| Подтверждённая жалоба | -20 автору, +5 заявителю |
| Оценка пользы Jev, уровни 0-4 | 0, 0, 0.1, 0.25, 0.5 |
| K | 100 |
| Дневной лимит минусующих реакций от участника | 5 |
| Минимальная карма для минусующей реакции | 1 |
| Нижняя граница кармы | -50 |
| Срок тишины | 14 суток |
| Убывание | 10% за каждые 30 суток после срока тишины |
| Надбавка за серию | +5% за неделю серии, не больше +25% |

Инвариант значений по умолчанию: наибольшее начисление Jev за сообщение строго меньше первой положительной реакции человека. Проверяется тестом.

### 3.5 Вопросы к Jev

Нормативная схема - `eval/questions.json`. Состав вопросов, типы и ключи - часть контракта и проверяются тестом на проводе. Вопросы хранятся в настройках чата (ключ `questions`), стартовое значение берётся из файла.

`state` - объект с полями `message`, `replied_to`, `previous_messages`, `sender_history`, `media_description`, `sender_profile`. Отсутствующее поле передаётся как `null`. Текст участника передаётся только в `state`; в `instructions` и `criteria` он не подставляется.

`sender_profile` - имя, ник и описание профиля (если Telegram его отдаёт); передаётся только для первого сообщения участника.

Итог по спаму считает код: `spam = max(spam_earnings_crypto, spam_topic_pivot, spam_channel_bait, spam_other_offer)`. Категория записи бани - имя вопроса с наибольшим значением; если оценка профиля выше, - `profile_promo`.

Вопрос `profile_promo` задаётся только при наличии данных профиля, `media_fits` - только при наличии `media_description` и `replied_to`. Вопрос `appeal_genuine` в оценку сообщений не входит и задаётся только при разбане отдельным запросом, где `state.message` - текст объяснения.

Размер запроса: до вызова оценивается весь JSON. Соблюдаются оба лимита: 64k токенов на запрос и 32k на `state` плюс самый длинный вопрос; оценка токенов - число знаков, делённое на 2. Порядок усечения: старые `previous_messages`, `replied_to`, `media_description`, `sender_profile` вместе с `sender_history`, затем `message` с пометкой об усечении. Если наименьший запрос не помещается, вызов не выполняется, в журнал пишется `context_too_large`.

Пороги по умолчанию: `is_thanks` 0.5, `is_answer` 0.5, `is_question` 0.5, `is_flood` 0.5, `media_fits` 0.5, `rude` 0.8. Предыдущих реплик в `state`: 8 (`previous_messages_count`). Порог реакции бота: уровень пользы 4 при уверенности не ниже 0.7; реакция по умолчанию 🔥 (`bot_reaction_emoji`).

### 3.6 Спам, баня, наблюдение

Первое учитываемое сообщение - первое полученное ботом `message` участника в данном чате. Импорт истории этот номер не меняет. Повторная доставка и редакция нового сообщения не создают.

Модерация применяется только к живым сообщениям, не к импортированным. Правила применяются сверху вниз, первое подошедшее прекращает разбор. «Текст судится» означает, что участник - новичок или на испытательном сроке (раздел 3.6.0); для остальных оценка спама по тексту в правилах не участвует. Номер правила совпадает с полем `rule` решения функции `decide` в `src/sanctions.ts`.

| № | Условие | Действие |
|---|---|---|
| 2 | карма участника ≥ `protect_threshold` и (текст судится и `spam` ≥ `spam_review_threshold`, или новичок и `profile_promo` ≥ `profile_auto_threshold`) | если текст судится - карточка админам; иначе ничего |
| 3 | текст судится и `spam` ≥ `spam_auto_threshold`, или первое учитываемое сообщение новичка и `profile_promo` ≥ `profile_auto_threshold` | парилка |
| 4 | испытательный срок и `spam` ≥ `probation_review_delete_threshold` | удалить сообщение, карточка админам |
| 5 | текст судится и `spam` ≥ `spam_review_threshold` | карточка админам «Похоже на спам, реши», сообщение остаётся |
| 6 | иначе | ничего |

Пороги по умолчанию: `spam_auto_threshold` 0.90, `profile_auto_threshold` 0.80, `spam_review_threshold` 0.30, `probation_review_delete_threshold` 0.30, `protect_threshold` 100. Размеченного набора спама для калибровки порогов нет; пороги подбираются по чату.

Если участник уже в бане или его парилка ещё выполняется, новое сообщение со спамом только удаляется, без второй реплики и без карточки. Сообщение новичка из одного медиа без подписи, которое не удалось описать, при отсутствии санкции даёт карточку админам.

Режим наблюдения: при первом подключении бота к чату сервер сохраняет `observation_started_at`. До `observation_started_at + 7 × 24 часа` чат в режиме наблюдения. Состояние переживает перезапуск. Импорт истории начало не сдвигает. Досрочного отключения нет. Админ может продлить режим настройкой `observation_until`. Что режим меняет, описано в разделе 3.6.3.

Парилка, бан и разбан - сохраняемый автомат состояний с идемпотентными шагами. Telegram и PostgreSQL общей транзакции не образуют: перед внешним вызовом сохраняется намерение, после успеха - результат; повтор продолжает с первого незавершённого шага. Состояние «завершено» ставится после всех обязательных шагов.

Шаги парилки: проверить роль участника (админа и владельца не трогать, карточка админам), удалить сообщение, ограничить участника, создать запись бани, отправить реплику с кнопкой «Я не спамер», при удалённом сообщении отправить админам карточку «Удалил спам и заглушил автора». Срок парилки `steam_hours`, по умолчанию 24 часа. Испытательный срок после разбана: следующие `probation_messages` (по умолчанию 5) сообщений; сообщение со ссылкой удаляется без карточки; действует правило 4 с порогом 0.30.

Разбан: текст объяснения от 1 до 500 знаков, проверка длины до Jev. Jev отвечает на вопрос `appeal_genuine` (`eval/questions.json`). Не ниже `appeal_accept` (0.7) - принято; ниже `appeal_reject` (0.3) - отказ; между - карточка админу с кнопками «Разбанить» и «Забанить».

Редакцией считается только обновление `edited_message`, в котором изменилось содержимое: текст, подпись или вложение. Telegram присылает `edited_message` и при смене тега отправителя (`sender_tag`); такое обновление ничего не меняет и оценку не запускает. Для сравнения хранится хэш содержимого, не текст. Если хэша у сообщения ещё нет, первое такое обновление только сохраняет хэш.

Редакция сообщения заменяет только оценку и событие Jev. Выполненные санкции автоматически не отменяются. Если редакция впервые пересекает порог, действует обычное правило. Если оценка после санкции упала ниже порога и текст судится, уходит карточка админу «Автор исправил сообщение, оно больше не похоже на спам; наказание осталось».

Реплики: набор в файле данных `data-static/jokes.json` с полями `replies` (подстановка `{name}`), `explanations` и `images`; выбор через переданный источник случайности. Формат файла фиксирован.

### 3.6.0 Спам судится по контексту и по автору

- В `state` есть поле `sender_history`: для первого сообщения участника `first message of this sender in the chat`, иначе `member of the chat, <N> earlier messages over <D> days`. N и D считаются по сообщениям участника в этом чате, включая импортированные.
- `previous_messages`: 8 последних реплик (настройка `previous_messages_count`).
- Четыре вопроса о спаме в `eval/questions.json` судят сообщение по `replied_to`, `previous_messages` и `sender_history`.
- Правила парилки и карточки по оценке текста применяются только к новичку и к участнику на испытательном сроке. Новичок - участник, у которого сообщений в этом чате, включая импортированные и текущее, не больше `spam_newcomer_messages` (по умолчанию 5; 0 отключает ограничение, и правила действуют на всех). К остальным участникам оценка спама по тексту не применяется: ни санкций, ни карточек. Оценка в базу пишется.
- Как считается число сообщений: для нового сообщения - сообщения автора, отправленные не позже него (позиция на момент отправки; задержанная оценка и сообщения, пришедшие следом, результат не меняют); для правки сообщения - все сообщения автора на момент правки.
- Правило о рекламном профиле применяется только к новичку по этому же счёту. Участник с историей, включая импортированную, по профилю не судится.
- Сообщения не от людей не судятся и целью `/spam`, `/report` и кнопок не становятся: автоматическая пересылка из привязанного канала (`is_automatic_forward`, отправитель 777000), сообщения от имени чата или канала (`sender_chat`), служебные сообщения (создание темы форума и прочие). В форуме ответ на служебное сообщение о создании темы считается сообщением без ответа.
- Правило 2 (участник с высокой кармой) для участника, чей текст не судится, карточку не создаёт.

Команда админа `/spam`: админ чата отвечает командой `/spam` (или `/spam@<имя бота>`) на сообщение.
- Право: свежий `getChatMember` отправителя команды, статус `creator` или `administrator`. Не админу команда не выполняется, команда удаляется, ответа в чат нет. Команда от имени чата или канала (анонимный админ) права не даёт: удаляется только команда.
- Действие: команда удаляется; сообщение удаляется; автор отправляется в парилку по шагам раздела 3.6 (ограничение, запись бани с категорией `admin`, шуточная реплика с кнопкой); текст сообщения сохраняется по правилам хранения спама.
- Режим наблюдения команду не блокирует.
- Цель - админ, владелец или бот: действие не выполняется, команда удаляется, админу-отправителю уходит личное сообщение с причиной.
- Команда без ответа на сообщение: удаляется, ничего не происходит.
- Повторная команда на то же сообщение второй раз ничего не делает.
- Защита высокой кармы на команду админа не действует.
- Если удалить команду не удалось, админам уходит карточка без кнопок; санкция выполняется.

### 3.6.1 Карточка админу

Карточки уходят в личные сообщения каждому админу чата (кроме ботов). Админ, который не нажал Start у бота, карточку не получит; карточка остаётся видна на экране админа.

Каждая карточка о сообщении содержит:
- имя участника и, если есть, `@username`;
- цитату сообщения: до 500 графемных кластеров, с пометкой об усечении; для сообщения без текста - вид вложения и подпись;
- ссылку на сообщение: `https://t.me/<username чата>/<message_id>` для чата с именем, `https://t.me/c/<идентификатор без префикса -100>/<message_id>` для чата без имени; ссылка даётся и текстом, и URL-кнопкой «Открыть сообщение»;
- категорию словами на русском («Лёгкие деньги и крипта», «Поддакнул и достал рекламу», «Заманивание в канал», «Навязчивая реклама», «Рекламный профиль», «Решение админа», «Ссылка на испытательном сроке»), а не именем вопроса;
- оценку спама процентом или «нет данных» и то, что бот сделал.

Текст сообщения, по которому создана карточка, сохраняется по правилу хранения удалённого спама (раздел 3.10): доступен только свежепроверенному админу чата, удаляется не позднее 30 суток, в том числе из копий в операциях. Если текста на момент создания карточки уже нет, карточка говорит «Текст недоступен, откройте сообщение по ссылке.» и даёт ссылку.

Текст участника в карточке - данные: разметка не применяется, длина ограничена лимитом сообщения Telegram.

### 3.6.2 Автоудаление, кнопки админа и ответ бота

Автоудаление:
- `spam_auto_threshold` по умолчанию 0.90. Новичок (раздел 3.6.0) с оценкой спама не ниже порога: сообщение удаляется, автор отправляется в парилку по шагам раздела 3.6, админам уходит карточка «Удалил спам и заглушил автора» с цитатой по разделу 3.6.1.
- Режим наблюдения это правило, команду `/spam` и кнопки админа не блокирует.
- Новичок с оценкой от `spam_review_threshold` до порога автоудаления: сообщение остаётся, админам уходит карточка.
- Ключ `spam_review_delete_threshold` есть в схеме настроек и участвует только в проверке порядка порогов (раздел 3.9); на решения он не влияет.

Кнопки карточки о спаме зависят от состояния сообщения и санкции:
- сообщение в чате, санкции нет: «Спам» и «Не спам»;
- сообщение в чате, участник в парилке: «Не спам» и «Забанить»;
- сообщение удалено: «Не спам, вернуть» и «Забанить»;
- после бана «Забанить» не показывается.

Действия:
- «Спам»: сначала проверяется роль участника; сообщение удаляется, автор отправляется в парилку, как при автоудалении.
- «Забанить»: сначала проверяется роль участника (админа, владельца и участника с непроверяемой ролью бот не трогает); сообщение удаляется, если оно ещё в чате; участник банится.
- «Не спам» (сообщение в чате): санкция, если есть, снимается; карточка закрывается.
- «Не спам, вернуть»: ограничение или бан снимается, запись бани удаляется, текст сообщения публикуется в чат от имени бота строкой `<имя автора>: <текст>`, испытательный срок не назначается. Для сообщения с вложением возвращается пометка о вложении и подпись. Слишком длинный текст обрезается по графемным кластерам с пометкой.

Ответ бота админу после каждого нажатия:
- всплывающий ответ на `callback_query` с итогом одной фразой;
- сообщение карточки правится (`editMessageText`): к тексту добавляется строка `Решение: <что сделано>. <имя админа>, <дата и время в часовом поясе чата>`, кнопки заменяются на оставшиеся допустимые действия;
- итог перечисляет выполненное и невыполненное, например «сообщение удалено, участник забанен» или «участник забанен; сообщение удалить не смог: <причина>»;
- правка карточки выполняется у всех админов, получивших её;
- отказ `editMessageText` решения не отменяет; итог остаётся во всплывающем ответе и на экране админа.
- После команды `/spam` админу-отправителю уходит личное сообщение с тем же итогом и кнопкой «Не спам, вернуть».

### 3.6.3 Язык карточек и режим наблюдения

- Карточка говорит только о том, что бот сделал, или просит решения.
- Режим наблюдения спам не затрагивает (раздел 3.6.2). В режиме наблюдения наказания за низкую карму раздела 3.7 не применяются и карточек админам не создают; что было бы применено, видно на экране админа. Кроме того, бот не ставит реакции на полезные сообщения и не отправляет недельную сводку. Теги кармы ставятся (раздел 3.12).
- Заголовок карточки - обычная фраза: «Удалил спам и заглушил автора», «Похоже на спам, реши», «Похоже на спам от участника с высокой кармой, реши», «Жалоба на сообщение», «Не смог удалить сообщение», «Участник - админ, наказывать не стал», «Не хватило прав, чтобы заглушить участника», «Объяснение при разбане вызвало сомнение».
- Оценка пишется процентом: «Уверенность: 98%».
- Порядок строк: заголовок; что сделано («Сделал: ...», если заголовок этого не говорит); участник; категория; уверенность; цитата; ссылка; строки решений.
- Цитата сообщения оформляется как цитата Telegram: сущность `blockquote` в `entities` с длиной в единицах UTF-16. `parse_mode` не используется, текст участника разметкой не становится.
- Слова «режим наблюдения», имена вопросов и служебные коды в карточках не используются.

### 3.7 Наказания, привилегии, жалоба

Наказания применяются в момент, когда карма пересекает порог сверху вниз. Повторное применение - только после нового пересечения.

| Порог | Действие | Вызов Telegram | Выход |
|---|---|---|---|
| карма ≤ -10 (`punish_media_karma`) | запрет ссылок, медиа и стикеров; минусующие реакции участника не учитываются | `restrictChatMember`: текст разрешён, остальное запрещено | карма > -10: права возвращаются к правам чата по умолчанию |
| карма ≤ -25 (`punish_mute_day_karma`) | мьют на 24 часа | `restrictChatMember` с `until_date` | срок истёк: действует строка -10 |
| карма ≤ -40 (`punish_mute_week_karma`) | мьют на 7 суток | `restrictChatMember` с `until_date` | срок истёк: действует строка -10 |

Наказание за карму записи в бане не создаёт и не применяется к участнику с записью в бане. Админы и владелец чата наказаниям не подлежат. В режиме наблюдения наказания не применяются.

Привилегии при карме ≥ `protect_threshold`:

| Привилегия | Изменение алгоритма | Наблюдаемый результат |
|---|---|---|
| Мягкая проверка | действует правило 2 раздела 3.6 | сообщение судимого участника со ссылкой и `spam` 0.6 остаётся в чате, админам уходит карточка |
| Защита от бана | правило 2 проверяется до правил 3 и 4 и перехватывает оценку текста и оценку профиля; для защищённого участника автоматические санкции недостижимы | вызовов `restrictChatMember`, `banChatMember`, `deleteMessage` нет |
| Вес голоса | `voter_weight` из раздела 3.4, действует для всех | реакция участника с кармой 100 даёт больше, чем с кармой 0 |
| Право дозора | жалоба сразу убирает сообщение | см. ниже |

Жалоба: команда `/report` ответом на сообщение. Команда удаляется из чата.
- Заявитель с кармой ≥ `protect_threshold`: сообщение удаляется, его текст сохраняется по правилам хранения спама, админам уходит карточка с кнопками «Подтвердить» и «Вернуть». «Вернуть» публикует текст от имени бота с именем автора.
- Остальные заявители: админам уходит карточка с теми же кнопками, сообщение остаётся до решения. «Подтвердить» удаляет сообщение, «Вернуть» закрывает карточку.
- Повторная жалоба на то же сообщение не создаёт второй карточки.
- Жалоба на сообщение админа, бота или на сообщение не от человека отклоняется.
- «Подтвердить» начисляет по таблице 3.4; награду получает первый заявитель.
- Лимит: 10 жалоб от участника за скользящие 24 часа (`report_daily_limit`).

### 3.8 Mini App: запуск и доступ

- В группах используется `InlineKeyboardButton.url` со ссылкой `https://t.me/<bot_username>?startapp=<context>`. Поле `web_app` в группах не используется.
- `<context>` имеет вид `<экран>_<chat_id>`, где экран - `lb`, `me`, `bans`, `appeal` или `admin`. Сервер берёт его только из `start_param` внутри подписанного `initData`. Неверный `start_param` или чат, которого бот не знает, отклоняется.
- Проверка `initData`: исходная строка разбирается на пары, `hash` исключается, пары сортируются по ключу и соединяются `\n`. `secret_key = HMAC_SHA256(key="WebAppData", message=bot_token)`. Ожидаемый хэш `hex(HMAC_SHA256(key=secret_key, message=data_check_string))` сравнивается за постоянное время. Затем `auth_date` не старше 24 часов.
- Без `start_param` (кнопка Mini App в профиле бота) клиент получает список чатов участника и выбирает чат; если чат один, он открывается сразу. Участие проверяется по базе, а если записи об участнике нет - через `getChatMember` в Telegram (статусы `creator`, `administrator`, `member`, `restricted`); проверяются не больше 20 известных боту чатов. Выбранный чат передаётся серверу и проверяется на участие при каждом запросе.
- При входе по `start_param` лидерборд, личные страницы и баня открыты любому, кто прошёл проверку `initData`.
- Экран админа и каждое его действие требуют свежего `getChatMember` со статусом `creator` или `administrator`. Положительный результат не кэшируется.

### 3.9 Экраны

Лидерборд: место, имя, карма за период; периоды неделя и месяц (скользящие 7 и 30 суток) и всё время.

Личная страница:
- сообщения: пять последних, самые заплюсованные, с наибольшим числом ответов; у каждого отрывок и ссылка на оригинал;
- цифры: карма, место, изменение за неделю, график кармы по времени, число благодарностей, число ответов на вопросы, число пойманных спамеров, серия активных недель;
- предупреждение об убывании, если до его начала меньше 3 суток.

`caught_spammers_count` - число уникальных участников, по сообщениям которых жалоба этого пользователя подтверждена админом; повторные подтверждения по одному участнику единицу не добавляют.

Баня: замаскированное имя, категория, объяснение из набора, картинка, дата. Маска имени - чистая функция с литеральными примерами в тестах: первый графемный кластер и три звёздочки. Публичный идентификатор записи непрозрачный.

Разбан: кнопка «Я человек», поле объяснения, результат.

Вкладки: «Разбан» видна только участнику с записью в бане, «Админ» - только админу чата (свежий `getChatMember` при открытии; отказ проверки прячет вкладку). Ссылка на скрытый экран открывает лидерборд. Защита экрана админа на сервере от видимости вкладки не зависит.

Реплики бота - жёсткий юмор, мат разрешён; объект шутки - спамер и спам.

Экран админа: состояние режима наблюдения и его продление, загрузка файла импорта и его состояние, операции с проблемами, убранные сообщения (до 30 суток), карточки, настройки чата с проверкой по схеме, журнал изменений.

Схема настроек - машиночитаемый файл и исчерпывающий перечень разрешённых ключей. Для каждого ключа: `name`, `type`, `default`, `nullable`, `minimum`, `maximum`, `enum` или схема элементов для составного значения, взаимные инварианты. Менять настройки может только свежепроверенный админ этого чата. Новая версия не меняет уже созданные операции и действует на операции, созданные после её записи. Общие правила: пороги в [0, 1]; `spam_review_threshold ≤ spam_review_delete_threshold ≤ spam_auto_threshold`; `appeal_reject ≤ appeal_accept`; `punish_mute_week_karma ≤ punish_mute_day_karma ≤ punish_media_karma`; веса в [-100, 100]; сроки больше 0 и не больше 366 суток; неизвестный ключ отклоняется. Конфликт версий: изменение несёт номер версии, на которой основано.

### 3.10 Хранение

- Бессрочно: оценки Jev, счётчики, ссылка на сообщение.
- Полный текст обычного сообщения в базу не пишется. Задание оценки хранит текст до завершения оценки и не дольше 24 часов.
- Отрывок до 200 графемных кластеров (`Intl.Segmenter`) живёт 7 суток (`excerpt_days`), затем остаётся только у лучших сообщений.
- Лучшие сообщения: не больше 10 на участника в чате (`best_messages_limit`), порядок `(положительная карма сообщения DESC, число ответов DESC, message_id DESC)`.
- Текст удалённого спама, сообщений, убранных жалобой, и сообщений, по которым создана карточка, доступен только свежепроверенному админу чата и удаляется не позднее 30 суток (`held_text_days`). Очистка после простоя догоняет пропущенное.
- Файл импорта удаляется после подсчёта и при любой ошибке. Незавершённое за 24 часа задание импорта прекращается.
- Отметки о полученных обновлениях Telegram хранятся 7 суток.

### 3.11 Импорт истории

Формат - JSON экспорта Telegram Desktop. Импорт доверяет файлу, загруженному действующим админом. Сравнение идентификатора чата защищает от ошибки и происхождение файла не доказывает; экран показывает это перед загрузкой. Лимит файла 50 МБ. Берутся сообщения за последние `import_days` (по умолчанию 90) суток. Сообщения оцениваются Jev теми же вопросами, кроме вопросов о профиле и медиа. Начисляются только плюсы; наказания, баны и карточки по истории не выдаются. Реакции учитываются как счётчик, без `pair_factor` и `voter_weight`. Задание импорта хранится в базе и продолжается после перезапуска. Одновременно в чате идёт один импорт. После импорта теги кармы расставляются той же очередью (раздел 3.12).

### 3.12 Тег с кармой

Рядом с именем участника видно его карму числом. Теги-звания не используются.

- Вызов: `setChatMemberTag(chat_id, user_id, tag)`. Тег 0-16 знаков, эмодзи запрещены. Работает только для обычных участников; боту нужно право `can_manage_tags`.
- Текст тега: шаблон из настройки `karma_tag_template`, по умолчанию `{n}`, где `{n}` - карма, округлённая до целого (`Math.round`), со знаком: `+321` для положительной, `-12` для отрицательной, `0` для нуля. Шаблон проверяется схемой: содержит `{n}`, без эмодзи, результат для числа из 6 знаков не длиннее 16.
- Настройка `karma_tag_enabled`, по умолчанию `true`.
- Тег ставится участнику, у которого есть хотя бы одно событие кармы. Участнику с кармой 0 без событий тег не ставится.
- Обновление: когда целое значение кармы участника отличается от последнего установленного. Последний установленный текст хранится в базе; совпадающий текст повторно не отправляется.
- Тег, который поставил человек и который не похож на тег кармы, бот не перезаписывает; участник помечается как не подлежащий тегу.
- Частота: не чаще одного обновления тега на участника в 10 минут (настройка `karma_tag_min_interval_minutes`); отложенное обновление берёт карму на момент отправки. Общий темп вызовов тегов на чат не больше 20 в минуту.
- Вызов выполняется как сохраняемая операция по общему правилу раздела 4, вид операции `set_tag`.
- Админы, владелец чата и боты: вызова нет. Роль берётся из ответа Telegram; ответ «участник - администратор» или «нельзя изменить» завершает операцию без повтора и без карточки, участник помечается как не подлежащий тегу до смены роли.
- Режим наблюдения теги не отключает: тег не санкция.
- Первичная расстановка после импорта или включения настройки идёт той же очередью с тем же темпом.
- При `karma_tag_enabled = false` новые теги не ставятся, уже поставленные не снимаются.

## 4. Таблица отказов

Общее правило внешних вызовов: 429 повторяется по `retry_after`. Сеть и 5xx повторяются до трёх попыток с растущей паузой. 400 и 403 не повторяются. Исчерпанный отказ пишется в журнал структурированно, без токенов и без полного текста обычного сообщения.

Каждый обязательный внешний вызов, меняющий состояние Telegram, выполняется как сохраняемая операция с полями `operation_id`, `operation_kind`, `idempotency_key`, `status`, `attempt_count`, `next_attempt_at`, `last_error_code`, `last_error_at`. Статусы: `pending`, `running`, `completed`, `failed`, `outcome_unknown`. После исчерпания повторов шаг выполненным не считается: операция получает `failed` и видна на экране админа. Если запрос мог быть принят Telegram, а ответ потерян, операция получает `outcome_unknown` и автоматически не повторяется, когда повтор может создать видимый дубль.

## 6. Тесты

- Самый высокий шов: обновление Telegram на входе, записанные вызовы Telegram и состояние базы на выходе.
- Каждая строка колонки «Тест» и каждая строка финишной черты покрыты тестом.
- Тесты на проводе для Jev и модели описания: уходящий запрос сверяется с литералом целиком.
- PBT: формулы кармы, маска имени, обрезка отрывка, перестановка пар `initData`.
- Проверка `initData`: фиксированные векторы, посчитанные независимо от проверяемого кода (значения в тесте литералами), и мутации каждого подписанного поля, порядка, `hash`, `auth_date`.
- `npm run test:coverage` пишет отчёт lcov в `coverage/` и копирует его по пути из переменной `QG_LCOV`, если она задана.

## 7. Что не входит

Ранги, теги-звания, персонажи, аватары, характеристики, ачивки, свой набор эмодзи, кросс-чатовый зачёт, общий список спамеров, расшифровка голоса, открытый сайт вне Telegram, генерация текста моделью, настройка обратного прокси и домена.
