# Жевчик

Telegram-бот для групповых чатов: карма за пользу, антиспам, Mini App. Судья - модель Jev (`jev-1.13.0`, версия закреплена).
Проект: `DESIGN.md` (зачем), `docs/spec.md` (что и как проверяется), `TASK.md` (финишная черта и таблица отказов с галочками).

## Состав

| Сервис | Что делает |
|---|---|
| `bot` | long polling, очередь оценок Jev, сохраняемые операции и автоматы (парилка, бан, разбан), плановые задачи (убывание, сводка, очистка, импорт) |
| `web` | Mini App и API на локальном HTTP-порту (`/healthz`, `/api/*`). HTTPS даёт внешний Caddy |
| `db` | PostgreSQL 16 |

Образ один (`Dockerfile`), команда выбирает роль: `node dist/main.js bot` или `node dist/main.js web`.

## Запуск

```
cp .env.example .env        # заполнить TELEGRAM_BOT_TOKEN, TYPESAFE_API_KEY, POSTGRES_PASSWORD
docker compose up -d --build --wait
curl -s http://127.0.0.1:8080/healthz    # {"status":"ok","db":"ok"}
```

Сборка идёт под `linux/arm64`. Контейнеры помечены как исключённые из автообновления.
Модель описания картинок необязательна: без `VISION_*` медиа не описывается, остальное работает.
`TELEGRAM_API_ROOT` и `JEV_API_URL` нужны только тестам и своему серверу Bot API, в проде пустые.

## Разработка

```
npm ci
npm run typecheck && npm run lint
npm test                 # сам поднимает временный кластер PostgreSQL в .scratch/pg (нужны initdb и pg_ctl, PG_BIN)
npm run test:coverage    # пишет lcov в $QG_LCOV
npm run build && npm run budget   # сборка и проверка бюджета Mini App (150 КиБ Brotli)
```

Тесты идут на настоящей базе. Двойники есть только на трёх внешних границах: Telegram, Jev, модель описания
(`tests/support/fakes.ts`); время и случайность передаются явно. `TEST_DATABASE_URL` подключает уже запущенный сервер вместо временного.

## Устройство в двух абзацах

Любая внешняя работа - сохраняемая: обновление Telegram пишется в базу вместе с заданием на оценку (`processed_updates`, `evaluations`) одной транзакцией,
дальше воркер берёт задания по очереди чата. Всё, что меняет состояние Telegram, идёт через таблицу `operations` (статусы `pending`, `running`,
`completed`, `failed`, `outcome_unknown`, ключ идемпотентности), а многошаговые сценарии - через таблицу `flows` (повтор с первого незавершённого шага).
Настройки версионируются по чату; событие запоминает номер последней записи настроек в момент начала и живёт по ним.

Карма - сумма журнала `karma_events`, кэш в `members.karma` пишется той же транзакцией. Формулы - `src/formulas.ts`, сигналы лестницы - `src/ladder.ts`,
правила спама - `src/sanctions.ts` (`decide`), конвейер применения оценки - `src/pipeline.ts`.

## Решения исполнителя там, где спека молчит

- Серия: надбавка = 5% x число смежных активных недель серии (включая текущую), не больше 25%.
- Лидерборд «неделя» и «месяц» - скользящие 7 и 30 суток; сводка - прошлая календарная неделя чата, отправляется после 10:00 по времени чата (настройка `digest_hour`).
- Суточный лимит минусов и жалоб - скользящие 24 часа.
- Карточки админам уходят в личку каждому админу чата; кто не нажал `/start` у бота, тот карточку не получит, карточка остаётся видна на экране админа. В личке бот отвечает на `/start` одной строкой.
- В режиме наблюдения бот не ставит и реакции (в спеке перечислены удаление, ограничение, бан, отправка).
- `sender_profile`: имя, ник и био (если Telegram его отдаёт); только для первого сообщения участника. Личный канал и аватар в Bot API не доступны, периодической перепроверки профиля в спеке нет.
- Правки сообщения: оценка пересчитывается, начисление Jev заменяется парой «отмена и новое»; выполненные санкции не отменяются.
- `/report` от обычного заявителя: кнопки карточки те же («подтвердить», «вернуть»), «вернуть» без удалённого текста только закрывает карточку.
